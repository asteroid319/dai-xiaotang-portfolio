我的工作方式

我的工作方式很像“先把书读厚，再把书读薄”：先让信息充分进入，再等逻辑拼图成形，最后把复杂判断表达得简单、可用。

先把书读厚

我会从不同角度输入信息：行业、公司、用户、交易、财务、专家访谈、产品体验。一个问题在我脑海里像一副拼图，线索越多，边界越清楚。

等到拼图成形

信息积累到某个奇点时，我会突然看见这件事的全貌：它是什么，为什么会这样，关键变量在哪里。过了这个阶段，再做投资或业务判断会清晰很多。

再把书读薄

最后一步是有产品思维地表达逻辑。思考需要深度，但交付给别人时要深入浅出，让对方很快知道结论、依据、风险和下一步动作。

B 层四步优化取舍

Route A
手动评分框架：先把方案排得清楚

第一版我选择手动设计评分框架，因为 MVP 阶段最重要的是让推荐结果可解释、可调参、可演示。我把偏好匹配、时间成本、路线绕行、预算压力、库存可用性、同行人适配和风险惩罚拆成可计算项，先保证系统能稳定输出主方案和备选方案。

score(plan) =
preference * w_pref
- time * w_time
- route * w_route
- budget * w_budget
- availability * w_availability
- group_fit * w_group
- risk_penalty

这一版帮助我快速定位错配案例，也暴露出权重主观、跨场景适应性不足的问题。

Route B
场景动态权重：把不同出行情境分开处理

第二版我在手动评分基础上加入场景动态权重。亲子场景提高 group_fit 和 availability、压低 novelty；约会场景提高 atmosphere 和 route；低预算场景提高 budget、降低商业附加服务权重。

这一步让排序逻辑跟用户场景绑定起来，也让我把权重初始化、测试集校准、Memory 动态调权和商业指标接入纳入 B 层设计。

Route C
AI 自优化框架：用失败案例反向改配置

第三版我设计 optimizer agent，用执行结果、用户反馈、eval metrics 和 failure cases 反向调整候选生成、过滤阈值、评分权重、异常处理、追问策略、Memory 调用和附加服务触发。

考虑到稳定性和安全性，我把自优化边界限制在配置和权重层，核心执行代码保留人工审核，避免过拟合和不可解释调整进入下单链路。

Route D
Preference Learning / LTR：为真实反馈留下接口

最后我把 Preference Learning / LTR 的演进路径设计进方案：当有用户反馈后，用 user_context、plan_a、plan_b 和 user_preference 训练排序模型，把人工权重逐步迁移到数据驱动排序。

这一步在 Hackathon 阶段主要落在数据结构和评估口径上，为之后衡量接受、确认、下单和复用留下接口。

价值信号建模路径

  • 围绕 family_care、health、convenience、cost_sensitivity 四类本地生活高频 value，设计触发词、反例、冲突规则、TTL 和权重上限。
  • 让 intent_parser 在结构化 intent 之外输出 value_probe，包括 value_id、score、confidence、evidence span 和 token attribution。
  • 设计 current-first merge：当前明确表达优先，其次是当前轮 value probe，再用 recent memory / long-term memory 补充缺口。
  • 把合并后的 effective_value_weights 投影到 score_weights，供 B 层规划排序读取，同时保留 value_sources 和 value_merge_trace 便于回放。

模型微调与 Probe 实验

  • 冻结 Qwen3-4B 主模型，基于 1200 条中文本地生活样例训练 token-level weak supervision probe，探索价值信号是否能从 hidden states 中被稳定识别。
  • 缓存 36 层 hidden states，对每层训练 token probe，观察不同层对家庭照顾、健康、便利、预算敏感等信号的表达强度。
  • 实验中 Layer 11 取得 test macro AUC 1.0000，Layer 22 取得 macro F1 1.0000，为后续 embedding regressor / activation probe 提供对照组。
  • 我把第一版产品链路保持为 rule/text probe，训练版只有在抽取、解释和下游消融上稳定优于 baseline 后再进入排序链路。

“正大杯”全国大学生市场调查与分析大赛

基于 722 份问卷与上万条爬虫数据，完成轻食包子品类客群聚类与消费者决策因素量化分析。

这份国三作品聚焦轻食面点，具体落到“轻食包子”品类。研究从市场规模上升、行业标准不足和消费者信任缺口切入，用问卷、访谈、爬虫和文本挖掘建立数据底座，再用多模型验证购买决策因素。

数据与模型

  • 发放 1000 份问卷，有效回收 722 份；预调查回收 189 份，用于修正问卷结构。
  • 爬取京东评论 4401 条、小红书相关帖子 5000 条，结合访谈补充 B 端与 C 端视角。
  • 使用 SEM、KANO、Logit、灰色关联分析和 SWOT 交乘矩阵，分别验证购买意愿、产品功能优先级、细分人群差异和营销策略强度。

关键结论

  • SEM 显示产品差异化、渠道设计、营销策略和价格设计显著影响购买意愿，便捷性路径不显著。
  • 消费者画像分为健康追求型、口感追求型、快捷便利型和价格敏感型，需求分别对应低脂高蛋白、好吃、即食体验和性价比。
  • 营销建议聚焦短视频推广、直播带货和线上线下融合，用透明厨房、营养师解读、真实用户故事降低“伪健康”疑虑。
